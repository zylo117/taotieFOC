# 2026-11-17 实测结论：开环落点已达本底，问题在"停后闭环不动作" + FE 刻度 2×

## 测量条件
板子 AT32F403A + KTH7823，`0x16D=0`（内部源）、`0x124=1` 使能、`0x166=0`（滞后加速度项本来关着）、
`0x167=400`、kp=120000 ki=10000 kd=50。上位机 `scripts/tt_*.py`，`0x116` 每 ~12ms 采样。
编码器静止噪声本底 ≈ ±0.17° 峰峰 ≈ **±3 微步**（1 微步 = 0.05625°）。

## 1. 账本是精确的：不是多发脉冲
半圈 5 趟，运动中显式读 `0x134 MOTION_SCHEDULED_STEPS` 取峰值：**取值集合 = [3200]**，
一次不多一次不少；同趟编码器实走 3193.0~3209.2（散布 16 微步）。

## 2. 引擎不是原因：两种引擎散布相同
`0x187 bit1` 分流实测（`tt_winab_tmp.py`，同版固件 A/B）：

| `0x187` | 引擎 | 分流自检 | 平均 | 散布 |
|---|---|---|---|---|
| 0 | 连续 PWM | `0x185=1 0x186=2` | +2.09 | 12.02 |
| 2 | 窗口 DMA | `0x185=0 0x186=0 0x177=3` | +1.14 | 12.16 |

## 3. 停后不再走、滞后补偿本来关着
`tt_settle_tmp.py`：停后 +0.3s / +1.0s / +2.0s 累计只再走 −0.2 / −0.4 / −1.0 微步。
`0x166=0`、`0x151=0` ⇒ 滞后模型/补偿不参与。

## 4. 散布是"固定绝对落点误差"，不是每步累积（同一口径版本对照）
同一版 HEAD 扫五种行程（`60/1200/6000`，各 3 趟，`0x107=0`）与 `c756ffa` 对照
（`30/600/3000`，因其内部 `spr=12800`，减半后真实 pps 剖面相同）：

| 行程(微步) | c756ffa 平均/散布 | HEAD 平均/散布 |
|---|---|---|
| 1600 | +1.13 / 7.23 | +2.26 / 4.68 |
| 3200 | +1.71 / 7.36 | +0.65 / 5.42 |
| 4800 | −1.47 / 2.01 | +3.27 / 3.38 |
| 6400 | −0.45 / 0.77 | +1.42 / 1.08 |
| 12800 | +1.34 / 1.16 | +0.78 / 0.50 |

**两版没有一格里 c756ffa 明显更好**；绝对误差恒定 ±3~4 微步，每千步偏差随行程递减
（1.41 → 0.06），是固定绝对落点误差（= 编码器本底）形态，不是每步多走。

## 5. "c756ffa 更准"是刻度假象
`c756ffa` 自己的 FE 读数：走 1600 微步（真 90.03°）报 **+45.247°**、3200（真 180°）报
**+90.208°**、4800（真 270°）报 **+134.813°**、6400（真 360°）报 **−179.928°**——
**全部是真实角度的一半**，因为其 `micro_steps_per_round=12800`（真实 1.8°×200×32=6400）。
后果：① 它的"半圈"按钮 `spr/2` 实际转**一整圈**（实测 6400 微步 = 360°），整圈周期性误差
在积分里自抵消，这才是"看起来没问题"的来源；② 它上报的位移/误差是 2× 错标，`0x128` 指定
180° 会实际转 360°。**现在这版刻度是对的（1600 命令 = 实测 90.03°）。**

## 6. 【待修 A】停后位置环不动作（这才是"闭环不工作"）
`tt_fetrace_tmp.py`：`0x107=1`、命令 3200 微步，停车后连续 6 秒 40+ 个采样点，
**FE 冻结在 −1.043° 一微度都不动**，`0x116` 只在静止噪声带抖动，`0x11F=0`、`0x18C=64`。
kp=120000 对 1° 误差不产生任何修正 ⇒ 运动结束后修正通道被关死（嫌疑：SETTLE 之后的
门控条件 / `updateSettleStage` 结束即退出、保持逻辑不重新发脉冲）。
`tt_cl_tmp.py` 停后 1.5s 残差：闭环 3200 少走 35.1~41.4 微步（−2.0~−2.3°）4 趟全部同号；
闭环 6400 少走 29.4~46.6 微步。**开环同行程整圈残差只有 +0.6~+1.8 微步。**

## 7. 【待修 B】FE 刻度 2×
同上：编码器实测少走 **−2.1°**，而 FE 报 **−1.043°**，比例正好 2:1——与 `c756ffa` 的
"spr=12800 报一半"同源。要查"计划位置/参考角"与 FE 之间的换算是否还残留 2× 
（`micro_steps_per_round` / `steps_per_round` / 角度↔微步某处用了 12800 或 0.5 系数）。
FE 是半标，任何以 FE 为目标的整定（PID 自整定评分 `0x132`、滞后表、UI 误差显示）都会被带偏。

## 8. 下一步（按优先级）
1. 查停后修正门控：让位置环在 SETTLE 结束后仍可对静态误差发修正脉冲（或明确"停后就失能"
   的产品语义并与 UI 说明一致）。定位点：`updateSettleStage`（closed_loop_controller.cpp:1785-1833）、
   保持/修正发脉冲的入口，以及 `0x18C` 各位置位含义。
2. 查 FE 的 2×：从 `0x121` 写入/读出路径反查参考角换算，找 12800 / 0.5 系数残留。
3. 以上两条修完再回头谈"开环 ±3 微步本底"——那已经是编码器分辨率/齿槽级，不是计数逻辑。
