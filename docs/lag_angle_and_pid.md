# 滞后角（lag angle）与闭环 PID 整定说明

> 本文对应 2026-11 的提速/整定改造。旧名字「负载角 load angle」已全部改名为
> 「滞后角 lag angle」，寄存器地址不变。

## 1. 滞后角是什么，为什么不能补偿

步进电机拖动负载时必须维持一个**力矩角**：转子总是落后于定子磁场（也就是落后于
命令脉冲）一个角度，才能产生转矩。这个角叫滞后角。

- 它随**转速/转矩需求**变化（转速越高、负载越大，滞后角越大），
  实测本机：50RPM ≈ 0.66°、100RPM ≈ 0.88°、200RPM ≈ 1.18°。
- 它**不是丢步**。脉冲发完以后，转子会把这点滞后自己追回来（最终停在最后一个
  微步位置上），所以行程并不少。
- 因此**不能把它当成误差去补偿**。如果 PID 看到「实际 - 命令 = -1°」就多发脉冲去追，
  转子就会一直被推着往前跑（追一个物理上不存在的位置），表现为：
  越走越超前、停不下来、末端冲过头。这就是旧版「负载角前馈」最危险的地方。

正确做法（现在的实现）：

```
有效误差 = 跟随误差 - 滞后角表(当前转速)      // 把"物理必然"的偏差剔除
PID 只处理 |有效误差| > 死区 的部分            // 剩下的才是真丢步/真扰动
```

实现细节（`updateLagAngleFeedforward` / `updateLagAngleMilliDegrees`）：

| 细节 | 取值 | 理由 |
|---|---|---|
| 查表速度 | 30ms 平滑 | 表是"转速→滞后角"的稳态映射，不需要跟着 20kHz 速度噪声抖 |
| 低速淡出 | <6RPM 线性到 0 | 拟合截距/噪声在近零速会让符号翻转，而低速真实滞后只有零点零几度 |
| 变化率限幅 | 40°/s | 换向/起步时符号会变，不能让 3° 阶跃直接跳进控制环 |
| 残差死区 | 0.15° | 约 27 个编码器 LSB，远高于噪声；表误差不会让 I 项慢慢爬 |
| 上限 | ±5° | 只做安全网（1200RPM 实测约 3°） |

标定方法不变：网页「滞后角校准」跑速度扫描 → 上传拟合点 → 0x141 拟合并存 Flash。
每一点的滞后角 = 该转速稳态下的 -跟随误差（取平均）。本机 11 点拟合结果：
`lag(ω) = -0.006 + 0.1343 · ω^0.410`（ω 单位 RPM，结果单位度）。

## 2. 速度环为什么"改一点点就抖"——三个代码问题（已修）

1. **增益口径错了 100 倍。** 串级改造删掉了 `p_scale=0.01` 的隐藏倍率，
   但默认值/网页值没跟着改：网页上的 30 本意是 0.3，改完变成真·30。
   速度环输入输出都是 rps，增益 30 = 1RPM 误差给 30RPM 修正，环路增益大两个数量级。
2. **两个环的输出没有物理限幅。** `max_output=50000` 对 rps 输出等于不限幅，
   只能在 emitSteps 外面被 ±max_rpm 硬钳 —— 环路实际工作在 bang-bang 区。
   这也是"规划运动的加减速阶段消失、一上来就是最高转速"的直接原因：
   起步时 base=`start_rpm`、实测=0，速度误差≈2rps，×30=60rps，直接被钳到满速，
   规划斜坡第一拍就被补偿量顶穿了。
3. **速度反馈是单拍 1LSB 差分。** 1LSB=0.0055°，50us 内就是 18.3RPM，
   低通压不掉台阶还带 1ms 群延迟。现在改成约 1ms 固定窗口滑窗差分
   （量化 18.3→0.9RPM），控制再串 3ms 平滑、显示串 20ms 平滑。

另外修了一个反向 bug：补偿段用"正的速度大小"减"带符号实测速度"，
反向时误差凭空多出 2 倍速度。

现在的限幅（`setOutputLimit`，每拍按当前规划速度刷新）：

| 项 | 上限 |
|---|---|
| 位置环输出 | 规划速度的 30%（≥0.25rps，≤0.5·max_rps） |
| 速度环输出 | 规划速度的 20%（≥0.15rps，≤0.35·max_rps） |
| 总修正 | 规划速度的 50%（≥0.35rps，≤0.6·max_rps），且不允许把速度拉成反向 |
| 补偿变化率 | angle_accel（0x130） |

## 3. 增益单位（网页值 = 实际增益，没有任何隐藏倍率）

| 环 | 输入 | 输出 | 默认 | 合法上限 |
|---|---|---|---|---|
| 位置 Kp | 误差（圈，1°=1/360） | 附加速度 rps | 60（1°→0.167rps=10RPM） | 1000 |
| 位置 Ki | 同上 | 同上 | 10 | 1000 |
| 位置 Kd | 误差变化率 | 同上 | 0 | 100 |
| 速度 Kp | 速度误差 rps | 速度修正 rps | 0.3 | 10 |
| 速度 Ki | 同上 | 同上 | 0 | 10 |
| 速度 Kd | 实测加速度（微分先行） | 同上 | 0 | 1 |

旧固件的速度环数字要 ÷100 才是新口径（当年 30 = 现在 0.3）。
持久化版本 v3 会在迁移时把 PID 重置为新默认值并打印原因。

## 4. 运动收尾：补偿在减速时不能污染"段进度"（已修）

`emitSteps` 里曾把"记账值"钳到不超过"实发值"。补偿只要在减速（PID 认为超前），
实发就小于规划，记账跟着少记 → 规划累计永远到不了 `pulse_count_` →
运动停在 25220/25600（差 1.5%），状态机卡在 DECEL，`0x11F` 永远不为 0。

现在：**记账 = 规划走到哪（命令位置参考），实发 = 真正发了几个脉冲**，
两者之差就是补偿量。另外 DECEL 到 0 但还有剩余步数时，用一个小爬行速度把尾巴补完，
作为第二道保险。

## 5. 自动整定

### 5.1 指标

固件在 20kHz 控制环里算（不是上位机采样，不会漏掉尖峰）：

```
score = RMS(有效误差) + 0.35·峰值 + max(0, 后半程RMS - 前半程RMS)
```

- 罚抖动（RMS）、罚超调/掉步（峰值）、罚"越跑越偏"（后半程增长）。
- 有效误差已经扣掉滞后角，所以不会把物理滞后算成整定目标。
- `0x132` 分数（毫度）、`0x133` 样本数、`0x160` 峰值（毫度）。

### 5.2 工况（脚本 `scripts/tt_autotune.py`）

| 工况 | 模式 | 速度 | 加速度 | 说明 |
|---|---|---|---|---|
| 慢速正向 | 0 | 15%→25% max | 1.2·max | 低速摩擦/爬行 |
| 中速正向 | 0 | 35%→65% max | 2.4·max | 常规巡航 |
| 高速正向 | 0 | 50%→100% max | 5·max | 高速跟随 |
| 中速反向 | 1 | 35%→65% max | 2.4·max | 反向符号/补偿方向 |
| 急加速 | 0 | 30%→85% max | 14·max | 急启动/急停 |
| 急转弯往返 | 6 | 35%→75% max | 14·max | 换向 + 反向加速 |

`max` 默认 240RPM，硬上限 250RPM（本机 300~800RPM 有剧烈共振，先低速整定）。

### 5.3 安全约束（硬编码，不允许参数绕过）

- 每个试验：使能 → 跑完 → 等沉降结束 → **失能**。绝不提前失能（会丢最后几十个脉冲）。
- 每个试验后读 `0x108`/`0x15D`：堵转/故障立即中止，不用坏数据评分。
- 堵转判据（固件 `updateStallGuard`）：命令速度 >8RPM 且 200ms 窗口内**净位移** <100LSB
  → 停机 + 关脉冲 + 失能 + 锁存（`0x108` bit3 / `0x15D`），必须写 `0x15F=1` 清除。
  判据必须看整段净位移而不是逐拍增量：这台编码器静止噪声峰峰就有 26~31LSB，
  "每拍变化<2LSB"会被噪声不停清零（实测电机完全不动时守卫也不动作）。
  8RPM 在 200ms 内走 1750LSB，所以 100LSB 有 3 倍/17 倍双向余量。
  **验证状态**：400+ 次整定试验没有误触发；真正的"堵住轴让它不转"需要机械卡住，
  台架上没法做，触发路径只做了代码审查。本固件的 TMC UART 是关的，
  `0x102 运行电流=0` 并不会真的断电流，所以不能用电的方法制造堵转。
- 试验间冷却 250ms。

### 5.4 搜索策略

按 `vel_kp → pos_kp → pos_kd → vel_kd → pos_ki → vel_ki` 的顺序做几何步进（×2 / ÷2）
坐标下降，有改善就继续，整轮无改善就停。综合分 = 加权平均 + 0.25×最差工况
（防止某一个工况烂掉）。搜索只用 3 个代表性工况，最后用全部 6 个工况验证。

### 5.5 怎么跑

```powershell
# 上台自检（先确认行程比例/斜坡/匀速）
python scripts\tt_selftest.py ratio
python scripts\tt_selftest.py ramp
python scripts\tt_selftest.py steady

# 自动整定（约 4~6 分钟）
python scripts\tt_autotune.py --port COM9 --max-rpm 240 --rounds 3 --step 2.0
```

结束时会回写最佳增益、回读校验、写 `0x154` 存 Flash，并输出 `autotune_result.json`。

## 6. 新增/变更的寄存器

| 地址 | 名称 | 说明 |
|---|---|---|
| 0x15D | STALL_DETECTED | RO，1 = 堵转锁存（已停机+失能） |
| 0x15E | STALL_EVENTS | RO，累计堵转次数 |
| 0x15F | STALL_CLEAR | WO，写 1 清除锁存 |
| 0x160 | PID_TUNE_PEAK_MDEG | RO，本次试验峰值误差（毫度） |
| 0x161 | ENABLE_MODE | R/W，0=上位机 1=外部 EN 引脚(PC13 低有效)，**存 Flash** |
| 0x162 | ENABLE_STATE | RO，驱动器实际是否使能 |
| 0x163 | QUICK_STOP | WO 1=快速停车（按 0x11C 减速后就地收尾，急刹标定用） |
| 0x164 | EXT_EN_LEVEL | RO，外部 EN 引脚电平（2=上位机模式不适用） |
| 0x165 | COMP_RPS_MILLI | RO，当前补偿速度 mRPS（抖动归因） |
| 0x166 | LAG_ACCEL_COEF | R/W，滞后角加减速项系数，毫度/(RPM/s)，**存 Flash**，默认 0 |
| 0x167 | LAG_DEADBAND_MDEG | R/W，恒速段残差死区（毫度），**存 Flash**，默认 400 |

`0x13C~0x147`、`0x151`、`0x152` 的**地址全部不变**，只是代码/界面里的名字从
load angle 改成 lag angle；Flash 里滞后角表的魔数 `0x4C414E47` 也不变，已标定的表不用重测。

参数结构升到 **v4**（末尾追加 0x166/0x167 两项）。迁移时按各版本自己的结构长度校验，
v1/v2/v3 记录都能读出来并补默认值（v3 的最后 2 字节原本是 reserved，现在用作 en_mode）。

## 7. 闭环抖动：根因与修复（2026-11-10）

用户观察：**开环很安静，一开闭环轴就抖**；串口抓恒速段也能看到同样的现象。

根因（是代码，不是调参）：

1. **位置环在追转子的微步振铃。** 恒速段跟随误差 RMS 0.18°、峰峰 0.7°，
   而真实跟踪误差只有零点零几度 —— 多出来的是"转子每走一个微步的机械振铃"。
   kp=80 把它放大成 **±4% 的脉冲频率调制**（0x165 实测补偿 std 0.030rps、pp 0.145rps）。
2. **速度环把测速噪声当速度。** 3ms 平滑后速度估计仍有 σ≈8RPM 的噪声，
   kp=0.2 直接乘上去就是 ±1.6RPM 的脉冲调制。
3. **起步惯性暂态被当成丢步。** 第一拍脉冲频率就从 0 跳到 start_rpm，转子跟不上，
   前 10ms 的 -2° 误差被 PID 补掉（补偿尖峰 +0.2rps，积分正好 0.7°）。

修法：

- 位置环误差先过 **2ms 一阶低通**；速度环加 **2% 规划速度的死区** + **3ms 输出低通**；
- **起步 20ms 屏蔽**两个环（这段只让转子跟上，不修正）；
- 滞后角改用**指令速度**（磁场转速就是指令速度，不是实测速度），5ms 平滑、200°/s 变化率。

实测（100/150/200RPM 恒速）：

| | 改造前 | 改造后 |
|---|---|---|
| 补偿速度 std | 0.030 rps | **0.008 rps** |
| 补偿速度 pp | 0.145 rps（±4.4%） | **0.052 rps（±1.6%）** |
| 150RPM pp | — | 0.029 rps |

## 8. 短行程末端多转（1 圈 +0.76°）

分解成两段：

1. **起步惯性暂态**：首拍脉冲从 0 跳到 start_rpm，转子的惯性跟不上，
   前 ~10ms 的 -2° 误差被位置环补掉，正好多走 0.7°。→ 用 20ms 起步屏蔽解决。
2. **加减速段的滞后角大于表值**（要额外提供 J·a 的转矩）。试过把这一项建模成
   ΔL ≈ c·a（0x166）：正向确实从 +0.94° 降到 +0.5°，但**反向从 -0.9° 恶化到 -1.6°**，
   说明正反向真实滞后角并不对称（重力/预载），一个线性项没有普适好处，
   所以默认关闭（0），需要时在网页上打开并单独标定。

现状（240RPM 以内、空载）：

| 工况 | 末端误差 |
|---|---|
| 正向 1 圈（120→250） | +0.45°（原 +0.76°） |
| 正向 1 圈（120→1000） | +0.4° |
| 反向 1.25 圈 | -1.5° |
| 急转弯往返 2 圈 | -0.8° |

**残余的正反向不对称是标定问题，不是增益问题**：滞后角表是带载标定的，
当前空载下正向偏小、反向偏大。带载重新标定后应把 0x152 设回 100；
若仍不对称，再用 0x166/0x167 兜。

## 9. 使能来源（0x161）

外部脉冲模式下，PLC/主控的 EN 才是真正的急停线，而网页上也有使能/失能按钮 ——
两者抢同一个驱动器 EN 脚会互相打架。现在二选一：

- `0x161=0`（默认）：上位机控制，`0x124/0x125` 直接写 EN；
- `0x161=1`：**PC13 低电平使能**是唯一权威。上位机只能"撤销许可"（失能），
  不能强行使能；故障（编码器/磁场/堵转）永远能压住 EN；引脚为高时 `startMotion` 直接拒绝。

参数写 Flash（0x154），网页连上时读 0x161 同步下拉框，并每秒回读 0x162/0x164 显示状态。

## 10. 急刹冲击标定

`0x163=1` = 快速停车：按 0x11C 的加速度减速到 0 后就地收尾（不是 `stopMotion` 的瞬间关脉冲），
整定器能在减速段继续采样。

两只整定器都有"急刹冲击"工况：恒速跑 0.45s → 快速停车 → 评分（含峰值）。
它只参与最终验证、不参与增益搜索（否则会把正常跟随的整定带偏）。
实测：评分 1.03°、峰值 1.56°（240RPM、3360RPM/s 减速）。
